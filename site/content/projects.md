## 빨래집사 — 무인빨래방 AI 운영 에이전트

2026 AI Agent Challenge (네이버 커넥트재단) · 팀 도원결의(2인) · 데모데이 @ NAVER 1784

### 기간과 상태

2026년 7월 ~ 8월 · **완료** — 우수 사례로 선정되어 네이버 커넥트재단 캠페인 인터뷰에 참여했습니다 (2026.08.14).

### 목적

무인빨래방에서는 세탁이 끝난 빨래를 찾아가지 않으면 다음 손님이 기계를 쓰지 못하고, 사장님이 CCTV를 보거나 직접 연락해야 합니다.
**기계를 바꾸지 않고 콘센트에 스마트플러그 하나만 꽂아서** 방치된 세탁물을 자동으로 감지하고, 손님과 사장님에게 단계적으로 알리는 것이 목표였습니다.

### 내 역할

2인 팀에서 **서버 전체를 담당**했습니다. 화면(고객 QR 화면, 사장님 대시보드)은 팀원이 맡았습니다.

- 센서 데이터를 받는 서버 입구(`POST /ingest`)와 조회 API (Express)
- 데이터베이스 설계와 SQLite → Supabase 전환
- 세탁 상태 판단 로직(상태 머신): 대기 → 세탁 → 탈수 → 종료 → 수거 / 방치
- 방치 시 단계별 알림(Web Push)과 중복 발송 방지
- 실제 매장 스마트플러그·문 열림 센서 연동과 전력 실측

### 과정과 선택 이유

1. **실측**: 실제 세탁기의 전력을 직접 측정했습니다.
2. **기준 결정**: 측정 데이터로 세탁 시작·탈수·종료 기준값을 정했습니다.
3. **구현**: 상태 판단 → 방치 판단 → 알림 순서로 서버 기능을 만들었습니다.
4. **배포**: 화면과 서버를 하나로 묶어 배포했습니다.

- **기준값은 짐작하지 않고 실측으로만 정했습니다.** 표준 코스를 1초 간격으로 기록해 탈수 구간과 휴지 구간을 확인했고, 그 값을 근거로 종료 판정에 여유 시간을 두었습니다.
- **수거 여부는 문 열림 센서로만 판단했습니다.** 손님이 "수거했어요" 버튼을 미리 누르면 잘못 처리되는 문제가 있어 버튼을 없앴습니다.
- **DB를 SQLite에서 Supabase로 바꿨습니다.** 매장은 한 곳이지만 여러 위치·기기에서 같은 데이터에 접근해야 했기 때문입니다.

### 배운 점과 개선 방향

- **배운 점**: 규칙과 설계를 문서(`CLAUDE.md`)에 먼저 정해 두니, AI 에이전트와 팀원이 같은 기준으로 작업할 수 있었습니다. 결정이 바뀔 때마다 문서를 고치고 모두가 그 문서를 보도록 한 덕분에, 역할을 나눠도 서로 어긋나지 않았습니다.
- **한계**: 이번에는 방치 대응 하나에만 집중했고, 매장 한 곳에서만 확인했습니다.
- **개선 방향**: 여러 매장과 다른 기종의 세탁기에서도 기준값이 맞는지 검증하고, 매장 전체를 관리하는 방향으로 넓히고 싶습니다.
